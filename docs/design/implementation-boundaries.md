# 현재 단계에서 무엇을 확정하고 무엇을 후속 설계로 남기는가

## 시스템 내부에서 추적해야 하는 개념

구체적인 데이터 모델은 이후 상세 설계에서 정의한다.
현재 업무 흐름에서는 다음 개념을 추적할 필요가 있다:

- 기획 문서
- 기획 원문 버전 또는 Snapshot
- 검토
- 검토 항목
- 개발 결정
- Open Question
- Blocker
- `blocked_scope`
- 기획자 답변
- 최종설계서
- 최종설계서 변경 이력
- 원문과 결정의 근거 관계
- 변경으로 영향을 받은 기존 결정

이 개념은 시스템 내부 추적 모델이다.
기획자용 UI는 Notion의 기획 원문과 개발 검토 결과로 구성한다.

## 현재 단계에서 확정하지 않는 구현 사항

이 문서는 업무와 제품 동작을 정의한다.
다음 사항은 후속 상세 설계에서 결정한다:

- Notion에서 신규 원문을 감지하는 방식
- Notion 원문을 로컬 Markdown으로 가져오는 방식
- 기획 원문 Snapshot을 저장하는 위치와 형식
- 의미 기반 변경 분석의 구체적인 구현 방식
- 검토 명세서를 시스템이 직접 읽는 방식
- 개발자가 AI 결과를 시스템에 등록하는 인터페이스
- Notion 개발 검토 페이지의 실제 생성 및 갱신 방식
- 기획자 답변을 시스템이 수집하는 방식
- 내부 상태 모델과 데이터베이스 스키마
- 최종설계서 버전 관리 방식
- DevFlow와 연결하는 구체적인 계약

## 제품의 완료 기준

이 시스템은 다음 조건을 만족해야 한다:

- 기획자는 기존 Notion 작성 방식을 유지한다
- 개발자는 신규 또는 변경된 기획을 놓치지 않는다
- 개발자는 기획의 의미 변경을 이전 원문과 비교할 수 있다
- 개발자는 현재 코드와 정책에 대한 영향을 확인할 수 있다
- 기술적 결정은 근거와 함께 개발자가 확정할 수 있다
- 제품 결정은 충분한 맥락과 선택지를 포함해 기획자에게 전달된다
- Blocker는 `blocked_scope`와 함께 관리되어 실제로 막힌 범위를 구분할 수 있다
- 기획자는 Notion에서 자신이 확인하거나 결정할 항목을 바로 파악할 수 있다
- 기획자 답변은 개발자가 재검증한 뒤 최종설계서에 반영된다
- 최종설계서는 DevFlow의 구현 기준으로 사용된다
- 개발 중 기획 변경은 원문 변경과 구현 영향을 분리해 추적한다
- 중요한 최종설계 결정은 기획 원문과 근거까지 역추적할 수 있다
