# 기획자에게 어떤 개발 검토 결과를 보여줄 것인가

## 기획자에게 보여주는 Notion 결과

기획자는 AI 분석 전문이나 개발 내부 로그를 읽지 않는다.
시스템은 개발자가 채택한 결과만 기존 설계서와 연결된 Notion 위치에 정리한다.

기획자용 결과는 다음 구조를 기본으로 한다:

```markdown
# 개발 검토

## 현재 상태

기획 확인 필요

- 개발 결정: 4건
- 확인 필요: 2건
- Blocker: 1건

## 개발자가 결정한 사항

### 소수점 처리 정책

기존 근태환경설정 정책을 재사용합니다.

- 이유: 동일 정책의 중복 정의를 방지합니다
- 반영: 기존 소수점 정책을 구현 기준으로 사용합니다
```

기획자가 답변해야 하는 항목과 Blocker는 같은 페이지에서 이어서 보여준다.

```markdown
## 확인이 필요한 사항

### 주 15시간 근무자의 공휴일 처리

- 선택 A: 주 15시간 유지
- 선택 B: 실제 근무일수에 따라 조정
- 개발 권장: 선택 A
- 이유: 기존 주간 정책과 계산 기준을 유지합니다
- 답변: 대기

## Blocker

### 공휴일 포함 시 주간 기준시간

- 막힌 범위: 주간 기준시간 계산 로직
- 현재 가능한 작업: 조회 API, 기본 저장 구조
- 답변: 대기
```

이 화면의 목적은 개발 내부 정보를 모두 전달하는 데 있지 않다.
기획자가 "개발자가 무엇을 결정했는지"와 "내가 무엇을 결정해야 하는지"를 바로 확인하도록 한다.
