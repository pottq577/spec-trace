# 기획 검토·변경 추적 시스템 문서는 어떻게 구성되는가

이 문서는 기획 검토·변경 추적 시스템의 전체 설계 문서를 연결하는 인덱스다. 시스템 정의부터 검토와 의사결정, 업무 시나리오, 변경 추적, 후속 상세 설계 범위까지 책임 단위로 문서를 분리한다.

## 문서 계획

- **대상**: 기획 검토와 구현 기준 확정을 담당하는 개발자
- **목표**: 필요한 설계 문서를 목적별로 찾아 읽고 전체 업무 흐름을 추적한다
- **범위**: 시스템 정의, 검토 모델, 업무 흐름, 변경 추적, 결정 근거, 후속 설계 범위
- **읽는 순서**: 시스템 정의 → 검토 모델 → 업무 흐름 → 추적 구조 → 후속 상세 설계

## 시스템 정의

시스템의 목적, 책임 경계와 주요 산출물을 정의한다.

- [시스템 정의와 역할](./system/definition.md): 해결하려는 문제, 핵심 원칙, 기획자·개발자·AI·시스템의 책임
- [문서와 산출물](./system/artifacts.md): 기획 원문, 검토 명세서, 기획자용 개발 검토, 최종설계서의 역할

## 검토와 의사결정

기획서를 어떤 기준으로 검토하고 발견한 항목을 어떻게 처리하는지 정의한다.

- [검토와 의사결정 모델](./review/review-model.md): 검토 기준과 분류, 개발 결정, Open Question, Blocker와 `blocked_scope`
- [기획자용 Notion 결과](./review/notion-output.md): 개발 결정과 기획자 확인 항목을 Notion에 보여주는 방식

## 업무 흐름

신규 기획서 검토부터 개발 중 기획 변경 대응까지의 실제 업무 흐름을 정의한다.

- [전체 업무 흐름과 상태](./workflow/overview.md): 공통 흐름, 반복 규칙, 상태 판단 기준
- [신규 설계서 검토](./workflow/new-design-review.md): 신규 기획 원문을 검토하고 최종설계서를 확정하는 흐름
- [개발 중 기획 변경 대응](./workflow/change-during-development.md): 개발 중 신규 기획 원문이 등록됐을 때 변경점과 개발 영향을 다시 검토하는 흐름

## 변경과 결정 추적

기획 변경과 최종 구현 기준 사이의 관계를 추적하는 기준을 정의한다.

- [기획 변경 비교 기준](./traceability/change-analysis.md): Source Diff와 Impact Analysis의 목적과 비교 대상
- [최종설계서와 결정 근거 추적](./traceability/decision-traceability.md): 기획 원문부터 검토사항, 결정, 최종설계서까지의 추적 관계
