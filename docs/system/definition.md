# 기획 검토와 변경 추적을 어떻게 운영할 것인가

이 문서는 기획자의 기존 Notion 작업방식을 유지하면서 기획 검증, 설계 결정, 변경 영향, 최종 구현 기준을 추적하는 시스템의 목적과 책임 경계를 정의한다.

## 한 문장 정의

이 시스템은 기획자의 기존 Notion 작업방식을 유지하면서 기획 변경을 추적하고, 개발자가 코드베이스와 도메인 정책을 기준으로 수행한 기획 검증, 설계 결정, Blocker, Open Question을 구조화해 기획자가 Notion에서 필요한 내용만 확인하고 결정할 수 있도록 지원하는 사내 기획·개발 의사결정 관리 도구다.

## 해결하려는 문제

현재 기획자는 AI를 사용해 설계서를 작성하고 결과 전문을 Notion에 등록한다. 요구사항을 수정할 때도 새로운 전문을 다시 등록하므로 개발자는 문장 차이보다 정책과 요구사항의 의미 변화를 직접 찾아야 한다.

개발자는 기획 원문만 읽고 구현할 수 없다. 현재 코드베이스, 선행 작업, 기존 도메인 정책, 관련 설계서, 이전 결정과 대조해 실제 구현 기준을 확정해야 한다.

이 과정에서 다음 정보가 흩어진다:

- 기획서의 결함과 모호한 요구사항
- 기존 코드와 기획의 충돌
- 선행 작업과 신규 기획의 충돌
- 개발자가 직접 해결한 기술적 결정
- 기획자가 결정해야 하는 제품 정책
- 개발을 막는 Blocker
- 각 결정의 근거와 트레이드오프
- 기획 원문과 최종 구현 기준의 차이
- 개발 중 기획이 바뀌었을 때 영향을 받는 기존 결정과 코드

이 시스템은 이 정보를 개발 흐름 안에서 추적하고, 기획자에게 필요한 결과만 Notion으로 전달한다.

## 핵심 원칙

시스템 설계와 이후 구현은 다음 원칙을 유지한다:

- 기획자는 기존 Notion 작업방식을 유지한다
- Notion은 기획자의 유일한 작업 인터페이스다
- 기획자에게 Git, commit, branch, revision, Markdown, 코드베이스 같은 개발 개념을 요구하지 않는다
- 기획 원문은 원본을 기준으로 그대로 보존하고 AI 해석은 검토 자료로만 사용한다
- 개발자가 기획 검증과 기술적 의사결정을 주도한다
- 제품 정책과 사용자 경험 결정은 기획자가 확정한다
- 기획자에게 AI 분석 전문이나 에이전트 로그를 노출하지 않는다
- 기획자에게 개발 결정, Open Question, Blocker와 필요한 근거만 업무 언어로 보여준다
- 중요한 결정에는 원문, 근거, 선택지, 트레이드오프, 채택 결과를 연결한다
- 최종설계서는 검증과 의사결정을 거친 실제 구현 기준이다
- 개발 중 기획이 바뀌면 변경된 의미와 현재 구현에 대한 영향을 함께 검토한다
- 확정된 원문 Snapshot, 답변, 결정, 최종설계 Revision은 이력을 덮어쓰지 않는다

## 역할과 책임

이 시스템은 기획자, 개발자, AI, 시스템의 책임을 분리한다.

### 기획자의 책임

기획자는 기존 업무방식을 유지한다.

1. GPT 등 기존 도구로 설계서를 작성한다
2. 결과 전문을 Notion에 등록한다
3. 수정이 필요하면 새로운 결과 전문을 Notion에 등록한다
4. 개발자가 전달한 개발 결정을 확인한다
5. 제품 결정이 필요한 Open Question과 Blocker에 답변한다

변경점 목록, 버전 번호, Diff, 개발 영향도, 검토 명세서는 개발자와 시스템이 관리한다.

### 개발자의 책임

개발자는 실제 구현 기준을 확정한다.

- Notion 기획 원문을 로컬 작업 자료로 확보한다
- 코드베이스와 기획을 대조한다
- 선행 작업과 기존 정책을 대조한다
- 설계서 내부의 논리적 결함과 누락을 검토한다
- Finding의 발견 유형, 결정 주체, blocking 여부를 분류한다
- 개발자가 해결할 수 있는 기술적 항목을 결정한다
- 제품 결정이 필요한 항목을 Open Question으로 관리한다
- 진행을 막는 항목에 Blocker와 `BlockedScope`를 연결한다
- AI가 제안한 결과를 검증하고 채택한다
- 기획자 답변을 다시 검증한다
- 최종설계 Revision을 확정한다
- 최종설계서를 DevFlow의 개발 기준으로 사용한다

### AI의 책임

AI는 개발자의 검토를 지원한다. 최종 판단과 채택은 개발자가 담당한다.

AI는 다음 작업을 지원할 수 있다:

- 기획 문서 비교
- 코드베이스와 기획 대조
- 정책 충돌 탐색
- 논리적 모순 탐색
- 관련 문서 간 불일치 탐색
- 누락된 요구사항 후보 탐색
- 선택지 생성
- 트레이드오프 분석
- 영향 범위 분석
- 검토 명세서 초안 작성
- 기획자용 결과 초안 작성

### 시스템의 책임

시스템은 기획 원문과 개발 의사결정을 연결한다.

- Notion 기획 문서와 변경 상태를 추적한다
- 신규 또는 갱신된 검토 대상을 개발자에게 알려준다
- 개발자가 채택한 Finding과 근거를 구조화해 저장한다
- 개발 결정과 기획자 결정을 이력으로 기록한다
- Open Question, Blocker, `BlockedScope`를 관리한다
- 기획자용 개발 검토 결과를 Notion에 제공한다
- 기획자의 답변을 개발 흐름에 연결한다
- 최종설계 Revision과 관련 결정의 추적 관계를 유지한다
- 검토가 끝난 최종설계서를 DevFlow의 입력 기준으로 연결한다
- 실제 구현 commit까지 추적 가능한 참조를 유지한다

개발자는 기존 ChatGPT, Codex, 기타 에이전트를 계속 활용한다. 시스템은 이 도구들의 검토 결과와 채택된 의사결정을 구조화하고 연결한다.
