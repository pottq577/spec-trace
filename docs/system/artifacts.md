# 기획부터 최종설계까지 어떤 문서를 관리하는가

## 문서와 산출물의 역할

기획 원문, 검토 명세서, 기획자용 개발 검토, 최종설계서는 서로 다른 역할을 가진다.

### 기획 원문

기획자가 Notion에 작성한 원본이다.
개발 검토 때문에 내용을 수정하지 않는다.

기획 원문은 다음 정보의 기준이다:

- 기획자가 실제로 작성한 요구사항
- 이전 원문과 신규 원문의 의미 변경
- 개발 결정의 출발점
- 최종설계서와 차이가 발생한 근거

### 검토 명세서

개발자가 AI와 함께 사용하는 상세 검토 문서다.
로컬 Markdown 문서를 기본 작업 형태로 사용한다.

검토 명세서는 다음 정보를 포함한다:

- 검토 기준
- 코드베이스 불일치
- 정책 충돌
- 문서 간 불일치
- 논리적 결함
- 요구사항 누락
- 모호한 요구사항
- 개발 결정
- Open Question
- Blocker
- 기획자 답변
- 최종 반영 결과

기획자에게는 검토 명세서 전문 대신 기획자용 개발 검토를 제공한다.

### 기획자용 개발 검토

기획자가 Notion에서 보는 결과다.
기획자는 이 내용만으로 현재 상황과 자신의 할 일을 이해할 수 있어야 한다.

기획자용 개발 검토는 두 종류의 정보를 중심으로 구성한다:

- **개발자가 결정한 사항**: 기획자가 확인하는 항목
- **기획자가 결정할 사항**: Open Question과 Blocker 중 기획자 답변이 필요한 항목

### 최종설계서

최종설계서는 실제 구현 기준이다.
기획 원문에 개발 결정, 기획자 결정, 기존 정책, 코드베이스 제약을 반영해 확정한다.

최종설계서의 중요한 정책은 관련 검토사항과 결정을 역추적할 수 있어야 한다.
